Public Bathrooms Audit — San Diego County

An open-source geospatial auditing system for documenting public restroom access across San Diego County. The project now combines a public-facing Leaflet map, field-audit workflow, Google Sheets data storage, Google Apps Script review automation, and GitHub Pages deployment.

Project overview

  • Goal: Maintain a reliable and auditable inventory of public restroom access.
  • Unit of analysis: Individual restroom locations represented as geospatial points.
  • Use cases: Field auditing, public access, service planning, data quality review, and policy analysis.
  • Status: Active development — the project has moved from a proprietary GIS workflow to an open-source web mapping and review system.

Current implementation

The current system replaces the earlier ArcGIS-centered workflow with a lightweight open-source stack designed for field use and iterative review.

Data model and update logic

  • Each restroom has a persistent globalid.
  • When an existing restroom is audited, its globalid is submitted as place_id.
  • Approved update submissions modify the matching restroom rather than creating duplicates.
  • Approved new submissions receive a new permanent ID before being added to the master dataset.
  • The public map reads only from the approved master dataset, not directly from the unreviewed submission log.

Field-audit interface

The audit form is hidden by default so users can browse the map without immediately interacting with a large form.

  • A floating Start an Audit button opens the form for a new restroom.
  • Clicking an existing restroom opens a popup with a Suggest a change action.
  • Existing restroom information can be prefilled while the current researcher's name, audit date, and new notes remain blank.
  • New restroom coordinates can be set by clicking the map or using device geolocation.
  • Desktop users receive a slide-out panel; mobile users receive a bottom-sheet style audit interface.

Data preservation and research QA

A major design requirement is preserving project-team edits and closure notes while still allowing new field observations to enter the system.

  • Team-curated closure information is treated as research history, not disposable metadata.
  • Existing team notes are not automatically copied into a new auditor's submission.
  • Approved updates are designed to modify selected fields without erasing unrelated baseline attributes.
  • The longer-term data model distinguishes between current restroom state, project-team review history, and field-audit history.

Engineering focus

  • Open-source replacement for a previously proprietary GIS workflow
  • Separation of public display, submission, review, and publication layers
  • Stable restroom identifiers for repeat observations over time
  • Approval-gated publishing for user-submitted field data
  • Preservation of project-team edits and closure notes
  • Mobile-friendly field auditing using geolocation and map interaction
  • Simple deployment architecture that can be maintained without a traditional server
